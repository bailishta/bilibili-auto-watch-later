# 稍后观看助手

将追踪的 B站 UP主发布的新视频添加到「稍后观看」列表，提供 Chrome 扩展和 Android 客户端。Chrome 支持自动检查，Android 使用手动检查。

**插件当前版本：2.0.0** · [下载插件](https://github.com/bailishta/bilibili-auto-watch-later/releases/download/v2.0.0/bilibili-auto-watch-later-v2.0.0.zip) · [更新日志](CHANGELOG.md) · [开发与发布](docs/DEVELOPMENT.md)

**Android 当前版本：2.0.0** · [下载 APK](https://github.com/bailishta/bilibili-auto-watch-later/releases/download/android-v2.0.0/bilibili-watch-later-android-v2.0.0.apk) · [安卓说明](android-app/README.md) · [安卓 Release](https://github.com/bailishta/bilibili-auto-watch-later/releases/tag/android-v2.0.0)

## 功能

- **自动检查新视频** — 定时扫描追踪名单中 UP主的最新视频，自动添加到稍后观看
- **一键导入关注** — 首次使用时一键导入 B站关注列表中的所有 UP主
- **手动管理名单** — 支持手动添加/移除 UP主，灵活控制追踪范围
- **观看历史过滤** — 自动检查前提前两倍检查范围开始采集，每天最多两次；按 B站账号保存视频编号和观看时间，按最大检查范围 × 2 + 1 天保留完整自然日，保留期内退出最近 500 条仍会跳过
- **可配置时间窗口** — 两端均支持设定「多久以内的视频算新视频」（12 小时～7 天）；Android 使用带下拉箭头的选择框
- **多个自动检查器（Chrome）** — 每个检查器独立设置名称、启停、每周各天时间、新视频范围，以及全部或指定 UP 主；同一时刻触发会排队执行
- **名单导入/导出** — 追踪名单可导出为 JSON 文件，支持在 Chrome 扩展与 Android 客户端之间互通
- **名单排序** — 按粉丝数、最近视频发布时间排序，每次检查自动更新并持久化数据，切换排序无需联网
- **配置备份** — 导出 JSON 备份，包含手动检查范围、排序、显示设置、记录保留周数和追踪名单（含已采集记录）；导入前显示概览，确认后替换配置，不包含登录信息。Chrome 另外备份独立检查器并恢复排程；Android 不包含自动检查器
- **更新分布** — 按自然周显示每天更新的 UP 主人数，点击某天进入无指针的 12 小时表盘，通过上午／下午切换查看全天。表盘按实际时间标记更新位置，下方直接列出精确到分钟的时间、人数与 UP 主头像、名字，无需再次展开，可切换本周与往周
- **Android 手机界面** — 首页、名单、更新、设置四个页面；支持系统／浅色／深色模式，首页可跳转 B站安卓 APP 的「稍后再看」

## 安装

### Chrome 扩展

1. 下载 [v2.0.0 Release](https://github.com/bailishta/bilibili-auto-watch-later/releases/tag/v2.0.0) 中的 `bilibili-auto-watch-later-v2.0.0.zip` 并解压（不要选择 GitHub 自动生成的 Source code）
2. 打开 Chrome，进入 `chrome://extensions/`
3. 开启右上角**「开发者模式」**
4. 点击**「加载已解压的扩展程序」**，选择解压后的文件夹
5. 安装完成后会自动打开引导页，可一键导入 B站关注列表

### Android 客户端

Android 2.0.0 使用 Jetpack Compose 原生手机界面，支持手动检查、缓存排序、更新分布和配置备份。功能和本地编译方式见 [安卓说明](android-app/README.md)。

1. 下载 [Android v2.0.0 Release](https://github.com/bailishta/bilibili-auto-watch-later/releases/tag/android-v2.0.0) 中的 `bilibili-watch-later-android-v2.0.0.apk`
2. 安装到手机，首次打开需通过内嵌 WebView 登录 B站
3. 登录后点击「导入关注列表」一键导入 B站 关注
4. 点击「立即检查」手动扫描新视频

安卓 APP 不提供自动检查器或后台排程。更新时优先覆盖安装；同签名升级保留本地名单、设置及登录。配置备份不包含登录信息。

## 使用说明

已有用户更新时，退出正在运行的检查，将新版解压到原扩展目录，然后在 `chrome://extensions/` 点击扩展卡片的重新加载并刷新管理页。沿用原扩展目录和安装项，避免卸载导致本地数据丢失；升级后旧排程会自动迁移。后续可通过「配置备份」保存和恢复配置。

- 点击扩展图标打开弹窗，可查看状态、手动触发检查
- 点击弹窗底部的「详细管理」按钮，在独立标签页打开管理中心
- 弹窗与管理中心均跟随系统自动切换浅色/深色模式
- 在管理中心添加/移除追踪的 UP主（支持 UID 或主页链接），搜索、排序及导入/导出名单
- 「手动检查范围」用于弹窗和管理中心的立即检查。在左侧「自动检查器」添加或编辑独立排程，选择全部或指定 UP 主；原有排程会自动迁移为「默认检查器」。删除所有检查器后自动检查保持关闭
- 观看历史采集提前量是对应检查器时间范围的两倍。例如周六 18:00 检查「1 天内」的视频，从周四 18:00 起按至少 12 小时间隔采集，每个本地自然日最多两次。多个检查器、启动补采和检查时的同步共用持久化限额；当天达到限额或未到间隔时使用本地记录，重启或修改检查器不增加采集次数。仅在至少一个检查器的提前采集区间内安排背景采集。
- 导入名单后，下一次自动检查或点击「立即检查」会补全粉丝数、最近视频发布时间和已采集的更新记录；之后切换排序、重新打开管理页均使用已保存的数据。接口失败时保留旧值，尚无数据的 UP主 排在最后。
- 「更新分布」支持收起，详细说明和保留周数位于折叠的「统计设置」中；切换整周／钟表及收起展开使用非线性动画，并尊重系统减少动态效果设置。按浏览器本地时区、周一到周日统计，每周、每天、半天和每分钟均分别按 UP 主去重。进入某天默认显示上午，可切换下午；无指针表盘保留 1–12 数字与刻度，精确到分钟的时间、人数、头像和名字在紧凑列表中直接展示，无需二次展开。切换星期与周数不访问 B站。可自定义保留最近 1～52 个自然周（含本周）的已采集记录，默认 3 周；缩短后立即清理范围外记录，延长后逐步积累，每位 UP 主最多 500 条，首次采集只含接口返回的最近视频（当前每次最多 10 条），不是完整历史。删除追踪 UP 主后其记录也不再计入面板
- 弹窗和管理页统一使用 B站网页的系统字体体系，Windows 优先微软雅黑，表单控件同步继承
- 左侧「配置备份」可导出或导入配置；这与名单导入／导出分开。导入会替换检查器、设置和名单，保留本机已处理视频记录和统计信息；检查或数据修改进行中时需等待结束再导入
- 插件点击「打开稍后观看」进入 B站网页；Android 点击「打开 B站 APP · 稍后再看」跳转安卓客户端，启动问题可在「设置 → 运行日志」查看

## 注意事项

- 需要登录 B站：插件使用浏览器登录，Android 使用 APP 内登录
- 自动检查依赖 Chrome 后台定时器，如果长时间未打开 Chrome 可能会延迟
- 本地观看记录按完整自然日计算生命周期：Chrome 取手动检查范围和所有已启用检查器范围的最大值，乘以 2 后向上取整为天，再加 1 天；Android 使用手动检查范围计算。保留日期包含今天，例如周六检查「1 天内」，保留周四零点起的周四、周五和周六记录，周六当天不会清掉周四记录。记录不按 500 条或更新统计的保留周数清理；按账号保存，过期记录在启动、采集、检查或调整设置时清理。只要历史中出现就视为看过，不要求看完。
- 每次同步最多读取 500 条，后续同步增量读取并留一分钟重叠；接口失败时继续使用保留期内的本地记录。Chrome 需在采集期间运行；关闭期间无法采集，启动后只能补回接口仍可返回的记录。Android 仅在手动检查时同步。旧版没有观看时间的本地记录在升级时开始一个保留周期。
- 首次同步时已超出 500 条范围、或两次采集间已被服务端淘汰的历史无法自动补回。卸载、清除插件／APP 数据会丢失本地记录；配置备份不包含观看记录，恢复配置后仍按新配置的生命周期清理本机记录。
- 插件基于 Manifest V3；Android 客户端要求 Android 8.0 及以上

## 项目结构

```
├── manifest.json          # Chrome 扩展配置
├── service-worker.js      # 后台服务（定时触发、消息路由）
├── content.js             # 内容脚本（B站页面代理请求）
├── core/
│   ├── api.js             # B站 API 封装（WBI签名、Cookie、请求）
│   ├── checker.js         # 核心业务（扫描新视频、导入关注）
│   ├── meta.js            # 发布时间、粉丝数与更新记录采集
│   ├── activity.js        # 本地记录合并、自然周聚合与排序
│   ├── schedules.js       # 检查器验证、旧设置迁移和下次运行时间
│   ├── backup.js          # 配置备份格式验证与字段筛选
│   └── storage.js         # chrome.storage 封装
├── popup/                 # 精简弹窗：状态、统计、检查与快捷操作
├── manage/                # 独立管理页：名单、检查器、更新分布和导入导出
├── onboarding/            # 首次安装引导页
├── icons/                 # 扩展图标
├── ui/                    # 共享配色、字体与深色模式
├── tests/                 # 缓存与排程测试、浏览器和真实扩展测试
├── docs/                  # 开发说明与发布说明
├── CHANGELOG.md           # 插件及 Android 更新日志
└── android-app/           # Android 客户端（Jetpack Compose）
```

浏览器插件使用原生 JavaScript + Manifest V3，无构建步骤；Android 客户端使用 Kotlin、Jetpack Compose 和 Room，通过 Gradle 编译。
